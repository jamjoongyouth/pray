# 교제 내용 질문지·답변 나눔 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **주의 — 이 계획은 절반이 브라우저 수작업이다.** Task 1~5는 노션 웹 UI에서 사람이
> 클릭해야 하는 작업이고, 에이전트가 대신 할 수 없다. 에이전트가 실행할 수 있는 것은
> Task 6(사이트 코드·문서 수정)과 Task 7(최종 검증 중 사이트 부분)뿐이다.
> 노션 작업의 산출물(공개 페이지 URL, 폼 URL 3개)이 Task 6의 입력이므로 순서를 지킬 것.

**Goal:** 사이트의 "교제내용 보러가기" 버튼이 회차별 질문지와 서로의 답변이 함께 있는
노션 공개 페이지를 열고, 누구나 로그인 없이 자기 답을 올려 즉시 공유할 수 있게 한다.

**Architecture:** 노션 데이터베이스 하나에 회차별 폼 뷰 3개(쓰기)와 갤러리 뷰 3개(읽기)를
붙인다. 회차를 가리키는 속성은 두지 않고, 회차별 문항 필드가 채워졌는지로 갈라낸다.
사이트 쪽 변경은 링크 한 줄과 안내 문구 한 줄뿐이며 JS·CSS·의존성 변경이 없다.

**Tech Stack:** Notion(무료 플랜, 폼·갤러리 뷰·웹에 공개), 순수 HTML(GitHub Pages)

## Global Constraints

스펙 `docs/superpowers/specs/2026-08-01-fellowship-sharing-design.md`에서 그대로 가져온다.

- 답변은 **제출 즉시 서로 공개**된다. 승인 절차를 넣지 않는다.
- **로그인을 요구하지 않는다.** 로그인 없이 제출되지 않으면 그 방식은 탈락이다.
- 이름은 **제목 속성** 하나로 받는다. 폼에서 필수, 안내문은
  `이름 또는 별명 · 익명으로 내려면 '익명'이라고 적어주세요`.
- 회차를 가리키는 **별도 속성을 만들지 않는다.**
- 리더용 숨김 스위치의 이름은 `숨김`이며 **체크하면 감춰진다**(기본 미체크 = 보임).
- 모든 폼 설명란 첫 줄은 `올린 답은 공개 페이지에 바로 보입니다.`
- 회차 대표 질문은 `index.html`의 "사흘의 기도" 세 질문과 **글자 그대로** 일치시킨다.
- 검색엔진 색인은 차단하지 않는다. 완화책은 위 고지 한 줄뿐이다.
- 사이트에 박는 링크는 **공개 페이지 URL 하나**다. 폼 URL은 사이트에 넣지 않는다.

## 파일 구조

사이트 쪽에서 손대는 파일은 셋뿐이고, 새로 만드는 파일은 없다.

| 파일 | 책임 | 이 작업에서의 변경 |
|---|---|---|
| `index.html` | 페이지 전체 마크업 | `.fellowship` 섹션의 링크 `href`와 안내 문구 (2줄) |
| `README.md` | 비개발자용 운영 안내 | 노션 운영법 항목 보강 |
| `docs/superpowers/specs/2026-08-01-fellowship-sharing-design.md` | 설계 근거 | 변경 없음 (참조용) |

`css/style.css`와 `js/main.js`는 **건드리지 않는다.** `.notion-btn` 스타일이 이미 있고
동적 동작이 필요 없다.

노션 쪽 산출물은 리포에 들어가지 않으므로, 완성된 URL 3종을 Task 5에서 기록해둔다.

### Task 1: 무료 플랜에서 폼이 실제로 동작하는지 확인 (게이트)

이 작업이 실패하면 나머지 전부가 무의미하다. 그래서 제일 먼저, 최소한으로 확인한다.
노션 무료 플랜의 폼 응답 수 제한은 문서로 확인하지 말고 **직접 제출해서** 확인한다.

**Files:** 없음 (노션 웹 UI 작업)

**Interfaces:**
- Consumes: 없음
- Produces: 판정 하나 — "1안으로 진행" 또는 "안 B(구글 폼)로 전환"

- [ ] **Step 1: 빈 데이터베이스 만들기**

노션에서 새 페이지를 만들고 이름을 `교제 나눔`으로 한다.
`/데이터베이스 - 전체 페이지`를 선택해 전체 페이지 데이터베이스로 만든다.
이 페이지는 **공개하지 않는다.** 리더만 보는 원본 저장소다.

- [ ] **Step 2: 임시 폼 뷰 하나 추가**

데이터베이스 상단 뷰 탭의 `+` → `양식(Form)` 선택. 뷰 이름은 `테스트`.
제목 속성 하나만 남기고 폼을 저장한 뒤, `공유` → 링크 복사.

- [ ] **Step 3: 로그아웃 상태에서 제출**

시크릿 창(또는 다른 브라우저)에 폼 링크를 붙여넣는다.

기대 결과:
- 로그인 화면이 뜨지 **않고** 폼이 바로 열린다
- 아무 값이나 넣고 제출하면 완료 화면이 뜬다
- 원래 브라우저의 `교제 나눔` DB에 그 행이 보인다

- [ ] **Step 4: 판정**

세 가지가 모두 통과하면 Task 2로 간다.

폼 뷰 생성 자체가 막히거나(유료 표시), 제출에 로그인을 요구하거나, 응답 수 상한
안내가 뜨면 **여기서 멈추고 사용자에게 알린다.** 그 경우 안 B(구글 폼 + 사이트 자체
답변판)로 전환하며, 이 계획의 Task 6은 링크 대상만 바뀐 채 그대로 쓸 수 있다.

- [ ] **Step 5: 테스트 흔적 정리**

`테스트` 폼 뷰와 제출된 테스트 행을 삭제한다. DB는 남긴다.

**Interfaces:**

  속성 이름의 철자가 다르면 필터가 조용히 어긋나므로 **글자 그대로** 만들 것.

기본 제목 속성(`이름` 또는 `Name`)의 이름을 `이름`으로 맞춘다. 타입은 제목 그대로 둔다.

- [ ] **Step 2: 회차별 문항 속성 9개 추가**

모두 타입은 **텍스트**로 만든다. 이름은 아래와 정확히 일치해야 한다.

```
1일차 문항 1
1일차 문항 2
1일차 문항 3
2일차 문항 1
2일차 문항 2
2일차 문항 3
3일차 문항 1
3일차 문항 2
3일차 문항 3
```

- [ ] **Step 3: 숨김 속성 추가**

이름 `숨김`, 타입 **체크박스**. 기본값은 건드리지 않는다(미체크 = 보임).

- [ ] **Step 4: 올린 시각 속성 추가**

이름 `올린 시각`, 타입 **생성 일시**. Task 4의 정렬 기준이다.

- [ ] **Step 5: 확인**

속성 목록에 `이름`(제목), 문항 9개(텍스트), `숨김`(체크박스), `올린 시각`(생성 일시)이
있는지 눈으로 확인한다. 회차를 가리키는 속성이 **없어야** 한다 — 있으면 지운다.

### Task 3: 회차별 폼 뷰 3개 만들기

**Files:** 없음 (노션 웹 UI 작업)

**Interfaces:**
- Consumes: Task 2의 속성 11개
- Produces: 폼 URL 3개. Task 5의 공개 페이지에 버튼으로 박힌다.

문항 문구는 아래를 그대로 쓴다. 리더가 나중에 노션에서 고쳐도 되지만, 지금은 이 문구로
완성해두어야 Task 7 검증이 가능하다. 회차 대표 질문은 `index.html`의 "사흘의 기도"와
같은 문장이다.

- [ ] **Step 1: 첫째 날 폼 뷰**

뷰 탭 `+` → `양식` → 뷰 이름 `첫째 날 · 8/7`.

- 폼 제목: `첫째 날 · 8/7 · 막 14:36`
- 폼 설명 (첫 줄이 고지):

```
올린 답은 공개 페이지에 바로 보입니다.
누구에게, 무엇을 기도하는가?
```

- 노출할 속성과 질문 문구:

| 속성 | 폼에 보일 질문 | 필수 |
|---|---|---|
| `이름` | `이름 또는 별명 · 익명으로 내려면 '익명'이라고 적어주세요` | 필수 |
| `1일차 문항 1` | `요즘 하나님을 어떤 분으로 부르며 기도하고 있나요?` | 선택 |
| `1일차 문항 2` | `지금 내가 "옮겨달라"고 구하고 싶은 잔이 있다면 무엇인가요?` | 선택 |
| `1일차 문항 3` | `"내 원대로 마시고"까지 붙이기 어려운 기도가 있다면, 어디가 걸리나요?` | 선택 |

나머지 속성(2·3일차 문항, `숨김`, `올린 시각`)은 폼에서 **모두 숨긴다.**

- [ ] **Step 2: 둘째 날 폼 뷰**

뷰 탭 `+` → `양식` → 뷰 이름 `둘째 날 · 8/14`.

- 폼 제목: `둘째 날 · 8/14 · 막 14:38–39`
- 폼 설명:

```
올린 답은 공개 페이지에 바로 보입니다.
반복하나, 포기하지 않고 나아가는가?
```

| 속성 | 폼에 보일 질문 | 필수 |
|---|---|---|
| `이름` | `이름 또는 별명 · 익명으로 내려면 '익명'이라고 적어주세요` | 필수 |
| `2일차 문항 1` | `같은 기도를 오래 반복해본 적이 있나요? 그때 무엇이 나를 계속 기도하게 했나요?` | 선택 |
| `2일차 문항 2` | `기도를 멈추게 만드는 것은 주로 무엇인가요?` | 선택 |
| `2일차 문항 3` | `이번 한 주, 포기하지 않고 다시 붙들고 싶은 기도 한 가지는 무엇인가요?` | 선택 |

나머지 속성은 폼에서 모두 숨긴다.

- [ ] **Step 3: 셋째 날 폼 뷰**

뷰 탭 `+` → `양식` → 뷰 이름 `셋째 날 · 8/21`.

- 폼 제목: `셋째 날 · 8/21 · 막 14:32–42`
- 폼 설명:

```
올린 답은 공개 페이지에 바로 보입니다.
함께 보는 결과가 과연 늘 선한가?
```

| 속성 | 폼에 보일 질문 | 필수 |
|---|---|---|
| `이름` | `이름 또는 별명 · 익명으로 내려면 '익명'이라고 적어주세요` | 필수 |
| `3일차 문항 1` | `원하던 대로 되지 않았지만, 지나고 보니 좋았던 일이 있나요?` | 선택 |
| `3일차 문항 2` | `아직 이해되지 않는 응답이나 침묵이 있다면 무엇인가요?` | 선택 |
| `3일차 문항 3` | `세 번의 기도회를 지나며 내 기도에서 달라진 점은 무엇인가요?` | 선택 |

나머지 속성은 폼에서 모두 숨긴다.

- [ ] **Step 4: 폼 URL 3개 복사해두기**

각 폼 뷰의 `공유` → 링크 복사. 세 URL을 메모장에 적어둔다. Task 5에서 쓴다.

- [ ] **Step 5: 회차가 갈리는지 즉석 확인**

시크릿 창에서 **첫째 날 폼**에 이름 `테스트`, 1일차 문항 1에 아무 답을 넣고 제출한다.

기대 결과: DB에 새 행이 생기고, `1일차 문항 1`만 채워져 있으며 2·3일차 칸은 비어 있다.
이게 회차 구분의 전부이므로 여기서 반드시 확인한다. 확인 후 그 행은 지운다.

### Task 4: 회차별 답변판(갤러리 뷰) 3개 만들기

**Files:** 없음 (노션 웹 UI 작업)

**Interfaces:**
- Consumes: Task 2의 속성, Task 3의 폼으로 들어온 행
- Produces: 갤러리 뷰 3개. Task 5에서 공개 페이지에 링크된 뷰로 삽입한다.

- [ ] **Step 1: 첫째 날 답변판**

뷰 탭 `+` → `갤러리` → 뷰 이름 `첫째 날 답변`.

- 카드 미리보기: `없음`
- 카드 크기: `중간`
- 표시 속성: `1일차 문항 1`, `1일차 문항 2`, `1일차 문항 3` (그 외 전부 끔)
  - 제목(`이름`)은 카드 머리글로 항상 표시되므로 따로 켤 필요가 없다
- 필터 (둘 다 걸어야 한다):
  - `1일차 문항 1` **비어 있지 않음**
  - `숨김` **체크 표시 안 됨**
- 정렬: `올린 시각` **내림차순**

- [ ] **Step 2: 둘째 날 답변판**

뷰 탭 `+` → `갤러리` → 뷰 이름 `둘째 날 답변`.

- 카드 미리보기: `없음`, 카드 크기: `중간`
- 표시 속성: `2일차 문항 1`, `2일차 문항 2`, `2일차 문항 3`
- 필터: `2일차 문항 1` 비어 있지 않음 **그리고** `숨김` 체크 표시 안 됨
- 정렬: `올린 시각` 내림차순

- [ ] **Step 3: 셋째 날 답변판**

뷰 탭 `+` → `갤러리` → 뷰 이름 `셋째 날 답변`.

- 카드 미리보기: `없음`, 카드 크기: `중간`
- 표시 속성: `3일차 문항 1`, `3일차 문항 2`, `3일차 문항 3`
- 필터: `3일차 문항 1` 비어 있지 않음 **그리고** `숨김` 체크 표시 안 됨
- 정렬: `올린 시각` 내림차순

- [ ] **Step 4: 필터가 실제로 가르는지 확인**

시크릿 창에서 첫째 날 폼과 둘째 날 폼에 각각 하나씩 제출한다
(이름은 `테스트1`, `테스트2`).

기대 결과:
- `첫째 날 답변` 뷰에 `테스트1`만 보인다
- `둘째 날 답변` 뷰에 `테스트2`만 보인다
- `셋째 날 답변` 뷰는 비어 있다

- [ ] **Step 5: 숨김 스위치 확인**

DB에서 `테스트1` 행의 `숨김`을 체크한다.

기대 결과: `첫째 날 답변` 뷰에서 즉시 사라진다. 체크를 풀면 다시 나타난다.

- [ ] **Step 6: 테스트 행 삭제**

`테스트1`, `테스트2` 행을 지운다. 실제 나눔 전에 DB가 비어 있어야 한다.

### Task 5: 공개 페이지 조립하고 웹에 공개

**Files:** 없음 (노션 웹 UI 작업)

**Interfaces:**
- Consumes: Task 3의 폼 URL 3개, Task 4의 갤러리 뷰 3개
- Produces: **공개 페이지 URL 하나.** Task 6이 이 값을 `index.html`에 박는다.

`교제 나눔` DB 자체를 공개하면 안 된다(모든 뷰와 원본이 노출된다). 별도의 새 페이지를
만들고, 거기에 갤러리 뷰만 **링크된 데이터베이스 뷰**로 끌어온다.

- [ ] **Step 1: 새 페이지 만들기**

노션에서 새 페이지 생성. 제목 `기도 · 교제 내용`.
맨 위에 주제 말씀 한 줄을 인용 블록으로 넣는다:

```
"아빠 아버지여 … 나의 원대로 마시옵고 아버지의 원대로 하옵소서." — 막 14:36
```

- [ ] **Step 2: 첫째 날 토글 만들기**

토글 블록 `▸ 첫째 날 · 8/7 · 막 14:36`을 만들고, 그 안에 순서대로 넣는다.

1. 굵은 글씨 한 줄: `누구에게, 무엇을 기도하는가?`
2. 문항 3개를 글머리 기호로 (Task 3 Step 1의 문항 문구 그대로)
3. 버튼처럼 쓸 링크 한 줄: `👉 내 답 올리기` — Task 3에서 복사한 **첫째 날 폼 URL** 연결
4. 구분선
5. 소제목: `함께 나눈 답`
6. `/링크된 데이터베이스 뷰` → `교제 나눔` 선택 → 뷰는 `첫째 날 답변` 선택

- [ ] **Step 3: 둘째 날·셋째 날 토글 만들기**

Step 2와 같은 구조로 두 개 더 만든다. 각각 해당 회차의 대표 질문, 문항 3개,
해당 회차 폼 URL, `둘째 날 답변` / `셋째 날 답변` 뷰를 넣는다.

첫째 날 토글은 펼쳐두고, 둘째·셋째 날은 접어둔다.

- [ ] **Step 4: 웹에 공개**

우측 상단 `공유` → `웹에 게시`(웹에 공개) 켜기.
`편집 허용`과 `댓글 허용`은 **끈 채로 둔다** — 읽기 전용이어야 한다.
게시 URL을 복사한다. 이것이 사이트에 박힐 유일한 링크다.

- [ ] **Step 5: 시크릿 창에서 전체 흐름 확인**

기대 결과:
- 로그인 없이 페이지가 열린다
- 토글 3개가 보이고 문항이 읽힌다
- `내 답 올리기`를 누르면 해당 회차 폼이 열린다
- 답변판 자리에 갤러리가 보인다 (아직 비어 있어도 정상)
- 페이지에서 DB 원본이나 다른 회차의 뷰로 새어나가지 않는다

- [ ] **Step 6: URL 3종 기록**

다음 세 가지를 사용자에게 전달하거나 메모해둔다. Task 6과 README에 들어간다.

- 공개 페이지 URL (사이트에 박음)
- 폼 URL 3개 (공개 페이지 안에서만 씀)
- `교제 나눔` DB URL (리더 전용, 숨김 처리할 때 들어감)

### Task 6: 사이트 링크·문구 교체와 README 보강

여기서부터 에이전트가 실행할 수 있다. Task 5의 공개 페이지 URL이 있어야 시작 가능하다.

**Files:**
- Modify: `index.html:119-124` (`.fellowship` 섹션)
- Modify: `README.md` (⚠️ 항목과 콘텐츠 수정표)

**Interfaces:**
- Consumes: Task 5가 만든 공개 페이지 URL
- Produces: 배포된 사이트. 이후 작업 없음.

- [ ] **Step 1: 현재 상태 확인**

Run: `grep -n "notion" index.html README.md`

기대: `index.html`에 `TEMP-CONTENT` 주석과 `href="https://www.notion.so"`가 보이고,
`README.md`에 노션 관련 줄 두 곳이 보인다.

- [ ] **Step 2: `.fellowship` 섹션 교체**

`index.html`의 아래 블록을

```html
    <section class="fellowship" id="fellowship">
      <h2 class="section-title">교제 내용</h2>
      <p class="fellowship-desc">수련회 교제 내용과 나눔 자료는<br>아래에서 확인할 수 있어요.</p>
      <!-- TEMP-CONTENT: href를 실제 노션 공개 페이지 URL로 교체 -->
      <a class="notion-btn" href="https://www.notion.so" target="_blank" rel="noopener">교제내용 보러가기 →</a>
    </section>
```

이렇게 바꾼다. `<실제-공개-페이지-URL>` 자리에 Task 5 Step 6의 공개 페이지 URL을 넣는다.

```html
    <section class="fellowship" id="fellowship">
      <h2 class="section-title">교제 내용</h2>
      <p class="fellowship-desc">회차별 질문을 읽고 내 답을 올리면<br>서로 나눈 답을 함께 볼 수 있어요.</p>
      <a class="notion-btn" href="<실제-공개-페이지-URL>" target="_blank" rel="noopener">교제내용 보러가기 →</a>
    </section>
```

`TEMP-CONTENT` 주석은 제거한다 — 더 이상 자리표시자가 아니다.

- [ ] **Step 3: 교체 결과 확인**

Run: `grep -n "notion.so\|TEMP-CONTENT" index.html`

기대: `notion.so` 자리표시자와 `.fellowship`의 `TEMP-CONTENT` 주석이 **사라져 있다.**
(히어로·푸터의 다른 `TEMP-CONTENT` 주석은 이 작업 범위가 아니므로 남아 있어도 정상이다.)

- [ ] **Step 4: README의 경고 항목 보강**

`README.md`의 2번 항목을 아래로 바꾼다. 폼을 새로 만들면 링크가 끊긴다는 점이
운영자가 가장 밟기 쉬운 지뢰라 여기에 적는다.

```markdown
2. **노션 교제내용 페이지의 "웹에 공개" 설정을 끄지 마세요.** 끄면 페이지의
   "교제내용 보러가기" 버튼이 죽습니다.
3. **노션 폼을 새로 만들지 마세요.** 폼을 새로 만들면 주소가 바뀌어, 교제내용
   페이지의 "내 답 올리기" 링크가 죽습니다. 질문을 바꿀 때는 **기존 폼을 고쳐서**
   쓰세요.
```

- [ ] **Step 5: README 콘텐츠 수정표 보강**

콘텐츠 수정표의 `교제내용` 행을 아래 세 행으로 교체한다.

```markdown
| 교제내용 질문 | 노션 `교제 나눔` DB의 해당 회차 **폼 뷰**에서 질문 문구 수정 (즉시 반영, 재배포 불필요). 폼을 새로 만들지 말 것 |
| 올라온 답 내리기 | `교제 나눔` DB에서 해당 행의 **숨김**을 체크 — 답변판에서 즉시 사라짐 |
| 답변판이 비어 보임 | 회차별 갤러리 뷰의 필터가 `N일차 문항 1 비어 있지 않음`인지 확인. 1번 문항을 비우고 낸 답은 안 보임 |
```

- [ ] **Step 6: 커밋**

```bash
git add index.html README.md
git commit -m "feat: 교제내용 링크를 노션 질문지·답변 나눔 페이지로 연결"
```

- [ ] **Step 7: 배포하고 반영 확인**

```bash
git push
```

1~2분 뒤 https://jamjoongyouth.github.io/pray/ 를 열어 "교제내용 보러가기" 버튼이
새 공개 페이지로 가는지 확인한다.

### Task 7: 실사용 검증

배포까지 끝난 뒤, 실제 참가자가 밟을 경로를 그대로 한 번 밟는다.
자동 테스트가 없는 구조라 이 수동 검증이 유일한 안전망이다.

**Files:** 없음

**Interfaces:**
- Consumes: Task 6까지의 결과 전부
- Produces: 통과/실패 목록

- [ ] **Step 1: 폰에서 NFC 경로 그대로 확인**

폰으로 NFC 키링을 찍거나 배포 URL을 직접 연다.

기대: 사이트가 열리고 "교제 내용" 섹션의 버튼이 노션 공개 페이지로 간다.

- [ ] **Step 2: 로그인하지 않은 상태로 답 올리기**

폰에서(노션 앱에 로그인돼 있다면 시크릿 브라우저로) 첫째 날 `내 답 올리기`를 눌러
이름 `익명`으로 답을 하나 제출한다.

기대: 로그인 요구 없이 제출되고 완료 화면이 뜬다.

- [ ] **Step 3: 즉시 공개되는지 확인**

공개 페이지로 돌아가 새로고침한다.

기대: 방금 낸 답이 `첫째 날 답변` 갤러리에 `익명` 이름으로 보인다.
둘째·셋째 날 답변판에는 나타나지 않는다.

- [ ] **Step 4: 숨김 스위치 확인**

리더 계정에서 `교제 나눔` DB의 그 행에 `숨김`을 체크한다.

기대: 공개 페이지를 새로고침하면 그 답이 사라진다.

- [ ] **Step 5: 모바일 로딩 속도 확인**

셀룰러 데이터로 공개 페이지를 연다.

기대: 답변판까지 읽을 만한 시간 안에 뜬다. 체감상 너무 느리면 갤러리 카드 크기를
`작게`로 낮추거나 표시 문항을 1개로 줄여 다시 확인한다.

- [ ] **Step 6: 테스트 흔적 정리**

검증용으로 제출한 행을 모두 삭제한다. 실제 기도회 전에 DB가 비어 있어야 한다.
