# 교제 내용 — 질문지 + 답변 나눔 — 설계 문서

날짜: 2026-08-01
상태: 사용자 설계 승인 완료

## 목적

사이트의 "교제내용 보러가기" 버튼이 여는 노션 페이지에서, 회차별 질문지를 읽고
각자 자기 답을 올려 서로 나눌 수 있게 한다. 지금은 버튼이 노션 홈(`https://www.notion.so`)을
가리키는 자리표시자 상태다 — `index.html`의 `TEMP-CONTENT` 주석 참고.

## 확정된 요구사항

사용자와의 브레인스토밍에서 확정한 것:

- **공개 범위**: 올리는 즉시 서로 공개. 제출 전에도 남의 답을 볼 수 있다.
- **신원**: 선택. 이름을 쓸 수도, 비워서 익명으로 낼 수도 있다.
- **질문지 단위**: 날짜별 세트 3회(8/7, 8/14, 8/21), 회차마다 여러 문항.
- **로그인**: 요구하지 않는다. NFC로 여는 페이지라 로그인 요구는 이탈로 직결된다.
- **검색엔진 색인**: 별도 차단 없이 그대로 진행한다(아래 "감수하는 리스크" 참고).

## 선택한 접근: 노션 폼 + 노션 답변판

검토한 대안:

1. **노션 폼 + 노션 답변판** (선택) — 백엔드 없음, 리더가 노션에서 전부 관리.
2. 구글 폼 + 사이트 자체 답변판 — 디자인은 더 낫지만 `js/main.js`에 시트 파싱 코드가 붙고,
   "노션에 질문지를 띄운다"는 원래 그림에서 벗어난다.
3. Supabase 백엔드 + 사이트 내 UI — 수정·삭제·실시간이 되지만 3주짜리 행사에 과하다.

선택 이유는 **운영 주체**다. 이 사이트의 코드를 고칠 수 있는 사람은 한 명뿐인데,
질문 문구는 회차마다 바뀔 수 있고 그건 리더가 직접 고쳐야 한다. 1안만 그게 된다.

### 전제와 그 근거

노션 공개 페이지는 **로그인 없이 글을 쓸 수 없다.** 댓글도 편집도 노션 계정을 요구한다.
"로그인 없이 답을 올린다"를 만족하는 노션 기능은 **폼(Notion Forms)** 뿐이다.
따라서 구조가 "읽기용 공개 페이지 + 쓰기용 폼"으로 갈라지는 것은 선택이 아니라 제약이다.

## 아키텍처

```
사이트 [교제내용 보러가기 →]  (index.html)
   └→ 노션 공개 페이지 "기도 · 교제 내용"
        ├ 회차 토글 × 3
        │   ├ 질문지 (읽기 전용 텍스트)
        │   ├ [내 답 올리기 →] ──▶ 노션 폼 뷰 (로그인 불필요)
        │   └ 답변판 ──────────── 같은 DB의 갤러리 뷰 (제출 즉시 반영)
        └ 상단: 주제 말씀 한 줄

[DB] 교제 나눔  ← 폼 뷰 3개와 갤러리 뷰 3개가 모두 이 하나를 바라본다
```

### 회차 구분 방식

**회차를 가리키는 별도 속성을 두지 않는다.** 회차별 문항 필드가 서로 다르므로,
1일차 폼으로 제출한 행은 1일차 문항 칸만 채워진다. 답변판 필터를
"1일차 첫 문항이 비어있지 않음"으로 걸면 회차가 저절로 갈린다.

제출자가 회차를 고를 필요도, 잘못 고를 여지도 없다. 노션 폼의 조건부 로직이나
기본값 지정 기능에 의존하지 않으므로 무료 플랜에서도 확실히 동작한다.

### DB 속성

| 속성 | 타입 | 용도 |
|---|---|---|
| 이름 | **제목** | 폼 안내 문구 "이름 또는 별명 · 익명으로 내려면 '익명'이라고 적어주세요" |
| 1일차 문항 1~3 | 텍스트(여러 줄) | 첫째 날 답변 본문 |
| 2일차 문항 1~3 | 텍스트(여러 줄) | 둘째 날 답변 본문 |
| 3일차 문항 1~3 | 텍스트(여러 줄) | 셋째 날 답변 본문 |
| 올린 시각 | 생성 일시 | 자동. 답변판 정렬 기준 |
| 숨김 | 체크박스 | 리더용. 체크하면 답변판에서 사라진다 |

`이름`을 일반 텍스트가 아닌 **제목 속성**으로 둔 이유는 갤러리 카드 때문이다. 노션
갤러리 카드는 제목을 항상 표시하고 숨길 수 없어서, 이름을 별도 텍스트 속성으로 만들면
카드마다 "제목 없음"이 함께 뜬다. 제목을 곧 이름으로 쓰고 폼에서 필수 입력으로 받되,
익명을 원하면 `익명`이라고 적게 안내한다. 실명·익명 선택권은 그대로 유지되고
빈 카드 문제가 사라진다.

회차당 문항 수는 **3개를 기본**으로 만든다. 리더가 나중에 노션에서 속성을 더하거나 빼도
되지만, 그때는 해당 회차의 폼 뷰와 갤러리 뷰의 표시 속성도 함께 손봐야 한다.

`숨김`을 "공개"의 반대 방향으로 둔 것은 기본값 때문이다. 노션 체크박스의 기본값은
꺼짐이라, "공개" 속성으로 만들면 리더가 매번 켜줘야 하고 "제출 즉시 공개"가 깨진다.

### 뷰 구성

- **폼 뷰 3개** (회차별): `이름` + 해당 회차 문항 필드만 노출. 폼 설명란 첫 줄에
  "올린 답은 공개 페이지에 바로 보입니다" 고지.
- **갤러리 뷰 3개** (회차별): 카드 미리보기 없음, 카드 제목(=`이름`) 아래에 해당 회차 문항 표시.
  - 필터: `해당 회차 첫 문항이 비어있지 않음` **그리고** `숨김이 미체크`
  - 정렬: `올린 시각` 내림차순

### 공개 페이지 레이아웃

```
기도 · 교제 내용
─────────────────
주제 말씀 한 줄

▸ 첫째 날 · 8/7 · 막 14:36        (토글. 지난 회차는 접어둔다)
    누구에게, 무엇을 기도하는가?
    문항 1 / 문항 2 / 문항 3
    [내 답 올리기 →]
    ── 함께 나눈 답 ──
    (갤러리 뷰 인라인)

▸ 둘째 날 · 8/14 · 막 14:38–39
▸ 셋째 날 · 8/21 · 막 14:32–42
```

회차 대표 질문은 사이트 "사흘의 기도" 섹션(`index.html`)의 세 질문과 일치시킨다.
세부 문항은 리더가 노션에서 작성하며, 코드 재배포 없이 언제든 바꿀 수 있다.

## 사이트 쪽 변경

작다. 세 군데뿐이다.

1. `index.html` — "교제내용 보러가기" 링크의 `href`를 실제 노션 공개 URL로 교체하고
   위의 `TEMP-CONTENT` 주석 제거
2. `index.html` — `.fellowship-desc` 문구를 질문지·나눔을 안내하는 내용으로 수정
3. `README.md` — 운영표에 노션 관리 방법 보강

JS·CSS 변경 없음. 새 의존성 없음.

## 감수하는 리스크

**노션 공개 페이지는 검색엔진에 색인될 수 있다.** 노션의 색인 차단 옵션은 유료 플랜
기능이라, 무료 워크스페이스에서는 막을 수 없다. 개인적인 나눔이 실명과 함께 검색 결과에
남을 가능성을 사용자가 인지하고 그대로 진행하기로 했다.

완화책으로 넣는 것은 **폼 상단 고지 한 줄**뿐이다("올린 답은 공개 페이지에 바로 보입니다").
쓰는 사람이 알고 쓰게 하는 것이 목적이다. 이름 칸에 `익명`이라고 적을 수 있으므로,
무겁게 느껴지는 내용은 각자 이름 없이 낼 수 있다.

부적절한 글이 올라오면 리더가 `숨김`을 체크해 답변판에서 즉시 내린다.

## 알려진 제약

- **본인이 나중에 수정·삭제할 수 없다.** 폼 제출 방식이라 제출자에게 수정 링크가 없다.
  고칠 일이 생기면 리더에게 부탁하거나 다시 제출해야 한다.
- **답변판은 노션 DB 뷰의 생김새를 따른다.** 사이트 톤(밤하늘·마루 부리)과 다르고,
  모바일 첫 로딩이 사이트보다 느리다. 이건 1안을 택한 대가로 받아들인다.
- **폼 링크를 새로 만들면 URL이 바뀐다.** 사이트에 박히는 것은 공개 페이지 URL이므로
  치명적이진 않지만, 공개 페이지 안의 폼 버튼 링크는 폼을 새로 만들 때마다 고쳐야 한다.

## 착수 전 확인 (구현 계획 1단계)

**노션 무료 플랜의 폼 응답 수 제한**을 실제로 확인한다. 폼 뷰를 만들고 로그아웃 상태에서
제출해보는 것이 유일한 확실한 검증이다. 여기서 막히면 구조를 그대로 둔 채 안 2(구글 폼 +
사이트 자체 답변판)로 전환한다 — 사이트 변경분이 링크 한 줄뿐이라 전환 비용이 낮다.

## 검증 항목

정적 페이지라 자동 테스트는 의미가 없다. 배포 전 시크릿 창에서 직접 확인한다.

- 로그인하지 않은 상태에서 폼이 열리고 제출되는가
- 제출한 답이 답변판에 바로 뜨는가
- 이름을 비우고 제출하면 "익명"으로 표시되는가
- `숨김`을 체크하면 답변판에서 사라지는가
- 회차별 답변판에 다른 회차 답이 섞이지 않는가
- 모바일에서 노션 페이지가 읽을 만한 속도로 열리는가
- 사이트의 "교제내용 보러가기" 버튼이 공개 페이지로 정확히 가는가

## 범위 밖 (YAGNI)

- 로그인·계정 (카카오 로그인 등)
- 사이트 안에서 답변을 렌더하는 자체 답변판
- 답변에 대한 댓글·좋아요
- 알림(새 답변이 올라왔을 때 푸시·카톡)
- 제출자 본인의 수정·삭제 기능
